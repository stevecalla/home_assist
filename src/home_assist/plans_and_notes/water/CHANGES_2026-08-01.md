# Water monitor — changes, 2026-08-01

A point-in-time review log for one build stretch: what changed, what broke, and why each call was
made. Written to be read once, top to bottom, by someone deciding whether they agree.

**This is not the status of the app.** `STATUS.md` in this folder is, and it is the one to keep
current. This file is deliberately frozen: a record that gets edited to stay true stops being a
record of what happened. When the next stretch of work lands, add a new dated file beside this one
rather than rewriting it.

Contains no credentials, paths, hostnames or meter ids — safe to commit.

## 8. Correction, 2026-08-02

**`-M freq` is not a valid rtl_433 option.** It was added to `DEFAULT_ARGS` and recommended for
`.env` on both machines. `rtl_433 -M help` settles it:

```
[-M time[:<options>]|protocol|level|noise[:<secs>]|stats|bits]
        Use "level" to add Modulation, Frequency, RSSI, SNR, and Noise meta data.
```

Two things were wrong at once: the flag does not exist, and even the intent was redundant —
`-M level` already supplies frequency. Worse, it is not ignored. rtl_433 rejects the unknown value
and the run produces **no** signal metadata, so `rssi`, `snr` and `freq` all come back null. That
reads as a dead antenna, which is the most expensive way for a wrong flag to fail.

| | |
|---|---|
| Fixed in code | `DEFAULT_ARGS` is now `-f 916.45M -s 1600k -R 223 -F json -M level` |
| Pinned by | a test asserting `-M level` is present and `-M freq` is absent |
| Tooltip | the `freq_mhz` column help named the wrong flag; corrected |
| **Action on each machine** | if `.env` sets `WATER_RTL433_ARGS`, it overrides the default — remove `-M freq` there too, or the columns stay blank |
